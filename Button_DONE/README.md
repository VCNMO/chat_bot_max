# «Портфолио педагога» для мессенджера MAX

Собирает ФИО, фотографии грамот за конкурсы и удостоверений о повышении
квалификации, задаёт вопросы по каждому документу и показывает сводку за последние
12 месяцев. Данные и фото хранятся в одном SQLite-файле.

В проекте две независимые версии:

| Версия | Файлы | Как открывается |
|---|---|---|
| **1. Чат-бот** | `bot.py` | обычный диалог с ботом, фото через 📎 |
| **2. Мини-приложение** | `mini_app.py` + `webapp/` | MAX Bridge, живая камера внутри приложения |

Обе версии используют одну и ту же базу `data/documents.sqlite3`, поэтому документы,
добавленные в одной версии, видны в другой. `bot.py` не изменялся при разработке v2.

# Версия 2 — мини-приложение с камерой

`mini_app.py` — Flask-бэкенд, `webapp/` — статический интерфейс. Внутри MAX
приложение получает `window.WebApp.initData`, показывает живой предпросмотр камеры,
делает снимок, даёт переснять его и только потом сохраняет документ.

## Что умеет

* ФИО с подсказкой из профиля MAX.
* Две кнопки: **Добавить грамоту** и **Добавить курс ПК**.
* Полноценная камера:
  * живой предпросмотр через `getUserMedia`;
  * съёмка кадра в JPEG с уменьшением до 1800 px по длинной стороне;
  * предпросмотр снимка, «Переснять» и «Использовать фото»;
  * переключение фронтальной/основной камеры;
  * выбор готового фото из галереи;
  * если камера недоступна — системная камера через
    `<input type="file" capture="environment">`.
* Анкета по документу с серверной и клиентской валидацией.
* Сводка за 12 месяцев: число конкурсов, курсов и сумма часов.
* Список документов с миниатюрами и переходом к добавлению новых.
* SQLite: фото хранится BLOB-ом, как в v1.

## Экраны

```
Загрузка → ФИО → Главный экран
                    ├─ [Добавить грамоту] → камера → снимок → анкета → главный экран
                    └─ [Добавить курс ПК] → камера → снимок → анкета → главный экран
```

Анкета конкурса: название, организатор, уровень, даты, год, результат.
Анкета КПК: название курса, организатор, даты, год, количество часов.

## Быстрый старт локально

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

В `.env` добавьте токен бота и включите режим разработки:

```dotenv
MAX_BOT_TOKEN=ваш_токен
MINI_APP_DEV_MODE=1
```

Запустите сервер:

```powershell
python mini_app.py
```

Откройте <http://127.0.0.1:8080>. На `localhost` камера работает и без HTTPS.
В dev-режиме вход через MAX отключён, поэтому в шапке показывается красная плашка
**DEV** — это удобно для проверки интерфейса, но недопустимо на публичном сервере.
Dev-режим использует ту же базу, что и бот; для экспериментов задайте отдельную:
`MINI_APP_DB_PATH=./data/dev.sqlite3`.

## Подключение к MAX

1. Разместите приложение на **HTTPS**-адресе. Локально проще всего туннель:

   ```powershell
   cloudflared tunnel --url http://127.0.0.1:8080
   ```

   или reverse proxy с TLS (пример Caddy):

   ```
   portfolio.example.ru {
       reverse_proxy 127.0.0.1:8080
   }
   ```

2. Откройте [business.max.ru](https://business.max.ru/self) → **Чат-боты** → ваш бот
   → **⋮** → **Настройки** → укажите URL мини-приложения и подпись кнопки.
   MAX принимает только `https://`, до 1024 символов.

3. Запустите бота, который пришлёт кнопку `open_app`:

   ```powershell
   python mini_app.py --bot
   ```

   В консоли появится публичное имя бота. `open_app` использует его, а не URL:
   URL уже сохранён в настройках бота. Если имя не определилось, задайте
   `MAX_BOT_PUBLIC_NAME` в `.env` (без `@`).

4. Откройте бота в MAX, отправьте `/start` и нажмите **📷 Открыть приложение**.

`--bot` запускает long polling. Не запускайте одновременно `bot.py` и
`mini_app.py --bot` с одним токеном: они будут перехватывать обновления друг у друга.
Если чат-сценарий v1 не нужен, достаточно `mini_app.py --bot`. Если нужен v1,
запускайте `bot.py` без `--bot` в mini_app и откройте мини-приложение по прямой ссылке
из настроек бота.

## Настройки (`.env`)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MAX_BOT_TOKEN` | — | токен бота; нужен для проверки `initData` и `--bot` |
| `MAX_BOT_PUBLIC_NAME` | из `GET /me` | публичное имя для кнопки `open_app` |
| `MINI_APP_HOST` | `127.0.0.1` | адрес Flask; для телефона в LAN — `0.0.0.0` |
| `MINI_APP_PORT` | `8080` | порт |
| `MINI_APP_DEV_MODE` | `0` | `1` — вход без MAX, только для разработки |
| `MINI_APP_DEV_USER_ID` | `1` | тестовый пользователь в dev-режиме |
| `MINI_APP_AUTH_TTL` | `3600` | срок жизни `initData`, секунды |
| `MINI_APP_PHOTO_TOKEN_TTL` | `7200` | срок жизни ссылок на фото, секунды |
| `MINI_APP_MAX_PHOTO_MB` | `25` | максимальный размер снимка |
| `MINI_APP_SECRET` | из токена | ключ подписи ссылок на фото (без токена — случайный на процесс) |
| `MINI_APP_DB_PATH` | `data/documents.sqlite3` | путь к общей базе |
| `MINI_APP_DEBUG` | `0` | debug-режим Flask |

## Как проверяется вход

На каждом запросе к `/api/*` клиент передаёт `window.WebApp.initData` в заголовке
`X-Max-Init-Data`. Сервер проверяет подпись по формуле MAX:

```
secretKey = HMAC_SHA256("WebAppData", bot_token)
hash      = HMAC_SHA256(secretKey, "\n".join(sorted("key=value")), hash исключён)
```

Дополнительно проверяется `auth_date` (по умолчанию не старше часа) и наличие
числового `user.id`. Сравнение хешей — constant-time. `initDataUnsafe` не используется.

Ссылки на фото (`/api/documents/<id>/photo?t=...`) подписаны HMAC и привязаны к
пользователю и сроку: `<img>` не умеет передавать заголовок с `initData`, поэтому
для миниатюр используется короткоживущий токен. Чужое фото по такому токену не
открывается.

## API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/health` | проверка сервера (без авторизации) |
| `GET` | `/api/bootstrap` | профиль, ФИО, поля анкет, сводка |
| `POST` | `/api/profile` | сохранить ФИО (`{"fio": "..."}`) |
| `POST` | `/api/documents` | фото + анкета (multipart: `kind`, `photo`, `fields`) |
| `GET` | `/api/documents/<id>/photo` | фото по подписанной ссылке |

## Камера: что важно знать

* MAX Bridge не даёт отдельного API камеры. Приложение использует стандартный
  `navigator.mediaDevices.getUserMedia`; в WebView MAX он работает по HTTPS.
* Если пользователь запретил камеру или устройство её не имеет, интерфейс
  предлагает снять документ системной камерой (`capture="environment"`) или выбрать
  файл. Это не тупик: анкету можно заполнить с любым снимком.
* Снимок сжимается на клиенте: максимум 1800 px по длинной стороне, JPEG ~0.88.
  Сервер дополнительно проверяет размер (25 МБ) и сигнатуру JPEG/PNG/WebP.
* `openCodeReader` из MAX Bridge — только QR-коды, для документов он не подходит.

## Production

Flask-сервер из `app.run` — для разработки. Для публичного запуска:

```bash
pip install waitress
waitress-serve --listen=127.0.0.1:8080 --call mini_app:create_app
```

Сверху нужен HTTPS reverse proxy (Caddy, nginx) или платформа с TLS. Webhook для
бота в v2 не реализован: `--bot` использует long polling. Для production
рекомендуется отдельный webhook-обработчик и WSGI-сервер; логика бота вынесена
в `run_bot`/`_handle_bot_update`, её несложно перенести в webhook.

Перед публикацией:

* выключите `MINI_APP_DEV_MODE`;
* задайте случайный `MINI_APP_SECRET` и храните `.env` вне репозитория;
* включите резервное копирование `data/documents.sqlite3`;
* ограничьте доступ к серверу и базе (там персональные данные и сканы);
* не включайте debug на публичном адресе.

```
/start
  └─ ввод ФИО
       └─ [🏅 Добавить грамоту] [🎓 Добавить курс ПК]
```

### Камера в v1

Bot API MAX не умеет программно открывать камеру. Бот присылает инструкцию, а
пользователь нажимает **📎 → «Камера»**, снимает документ и отправляет фото в чат.
Готовое фото из галереи тоже подходит. Камера «внутри» бота — это уже версия 2.

# Общее для обеих версий

## Сертификат Минцифры (важно)

`platform-api2.max.ru` подписан **Russian Trusted Root CA** (Минцифры), которого нет
в стандартном наборе сертификатов Python. Без него запрос падает с
`CERTIFICATE_VERIFY_FAILED`.

Код сам скачивает корневой сертификат при первом запуске и собирает общий CA-bundle
в `data/ca_bundle.pem`. Если скачать не удалось (закрыт доступ к `gu-st.ru`), возьмите
файл вручную:

<https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt>

и положите его как `data/russian_trusted_root_ca.pem`, затем перезапустите приложение.

Отключать проверку TLS (`verify=False`) нельзя — это небезопасно.

## База данных

Файл `data/documents.sqlite3` (SQLite, WAL). Фото документа хранится прямо в БД как BLOB.
Схема общая для v1 и v2.

```sql
CREATE TABLE users (
    user_id      INTEGER PRIMARY KEY,
    fio          TEXT,
    state        TEXT,      -- new | menu | await_photo | fill
    pending_kind TEXT,      -- competition | course
    draft_id     INTEGER,   -- незаконченный документ
    created_at   TEXT
);

CREATE TABLE documents (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id     INTEGER REFERENCES users(user_id) ON DELETE CASCADE,
    kind        TEXT,       -- competition | course
    photo       BLOB,       -- сам снимок документа
    photo_mime  TEXT,
    title       TEXT,       -- конкурс или курс
    organizer   TEXT,
    level       TEXT,       -- только для конкурса
    dates       TEXT,
    year        INTEGER,
    result      TEXT,       -- только для конкурса
    hours       INTEGER,    -- только для КПК
    completed   INTEGER,    -- 1 = анкета заполнена
    created_at  TEXT
);
```

Сводка «за последний год» считает документы, загруженные за последние 12 месяцев
(по `documents.created_at`), а не по году проведения.

Посмотреть данные можно любым SQLite-клиентом (например, DB Browser for SQLite) или так:

```powershell
python -c "import sqlite3; c=sqlite3.connect('data/documents.sqlite3'); print(*c.execute('select id,kind,title,year from documents'), sep='\n')"
```

## Ограничения

* Long polling удобен для разработки; для production нужен webhook (HTTPS/443).
* Один документ = одно фото. Редактирования и удаления документов пока нет.
* Нет OCR: поля заполняются вручную.
* Нет ролей и админки: ФИО вводится один раз и меняется на главном экране.
* Персональные данные (ФИО, сканы документов) лежат в SQLite — для реального
  использования нужны политика обработки ПДн, доступ к серверу и резервные копии.

## Куда развивать

* webhook вместо long polling;
* редактирование и удаление документов, несколько фото на документ;
* экспорт портфолио в PDF;
* OCR для автозаполнения полей;
* админ-панель и авторизация по номеру телефона (`request_contact`).

Документация MAX: <https://dev.max.ru/docs-api> и <https://dev.max.ru/docs/webapps/introduction/>.
